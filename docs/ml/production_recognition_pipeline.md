# Production Face Recognition & Enrollment Pipeline Documentation

## 1. Overview

The AutoRoll production face recognition and enrollment engine provides end-to-end processing for face detection, quality filtering, anti-spoofing liveness verification, ArcFace feature extraction, normalized mean template generation, and sliding-window temporal attendance decision confirmation.

---

## 2. Production Pipeline Flow

```
Frame (BGR)
  │
  ├── 1. SCRFD Face Detection (5-point facial landmarks, bounding boxes, detection confidence)
  │
  ├── 2. Quality Filtering (Resolution check, Laplacian blur variance, pose estimation)
  │
  ├── 3. Umeyama Face Alignment (112×112 RGB normalized face chip)
  │
  ├── 4. MiniFASNet Liveness Verification (ML score + Texture/FFT Moire heuristic = Combined Liveness Score)
  │
  ├── 5. ArcFace Feature Extraction (512-dimensional embedding vector)
  │
  ├── 6. L2 Vector Normalization (||v||₂ = 1.0)
  │
  ├── 7. Template Matching (Cosine similarity vs. enrolled student templates)
  │
  ├── 8. Sliding-Window Temporal Confirmation (3 observations within 1500 ms)
  │
  └── 9. Attendance Decision Generation (PRESENT / UNKNOWN / REJECTED_SPOOF / LOW_QUALITY / INSUFFICIENT_CONFIDENCE)
```

---

## 3. Model Architecture & Versioning

AutoRoll implements the `FaceRecognitionModel` abstract contract with dynamic model selection via `AUTOROLL_RECOGNITION_MODEL`:

| Model ID | Class Name | Backbone / Weights Path | Validated Threshold | Embedding Dim | Execution Backend |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `pretrained` | `PretrainedArcFaceRecognizer` | `models/pretrained/arcface_r50_webface_or_glint/model.onnx` | `0.0440` | 512 | ONNXRuntime (CUDA/CPU) |
| `autoroll_v1` | `AutoRollArcFaceRecognizer` | `models/trained/autoroll_arcface_v1/epoch_001.pt` | `0.0540` | 512 | PyTorch (CUDA/CPU) |

### Model Version Safety Guard
Every face template stored in the database records `model_id`, `model_version`, and `embedding_dimension`. Matching observations against templates generated by a different `model_id` triggers an explicit `INCOMPATIBLE_MODEL_TEMPLATE` rejection.

## 4. Student Face Enrollment Workflow

1. **Session Initialization:**
   `POST /api/v1/enrollment/start` creates a session tracking `student_code`, `full_name`, and `department`.
2. **Multi-Sample Frame Capture (5–10 samples):**
   `POST /api/v1/enrollment/{session_id}/frame` evaluates uploaded frames:
   - **Detection:** Rejects if `no_face` (0 faces) or `multiple_faces` (>1 face).
   - **Quality:** Rejects if `poor_quality` (blur variance < threshold or face < 80px).
   - **Liveness:** Rejects if `spoof_detected` (`combined_liveness_score` < 0.90).
   - **Extraction:** Extracts 512-dim ArcFace embedding and applies L2 normalization.
3. **Template Aggregation & DB Persistence:**
   `POST /api/v1/enrollment/{session_id}/complete` computes the normalized mean embedding template:
   $$\mathbf{v}_{\text{mean}} = \frac{1}{N} \sum_{i=1}^N \mathbf{v}_i, \quad \mathbf{v}_{\text{template}} = \frac{\mathbf{v}_{\text{mean}}}{\|\mathbf{v}_{\text{mean}}\|_2}$$
   Stores `StudentEmbedding` record with `model_id`, `model_version`, `embedding_dimension=512`, `sample_count=N`.

## 5. Temporal Confirmation & Attendance Decision Rules

Attendance requires **all** of the following conditions to be satisfied:
1. Face detected with confidence $\ge 0.50$.
2. Quality check passed (`is_quality_ok == True`).
3. Liveness verification passed (`combined_liveness_score >= 0.90`).
4. Template model compatibility matched (`template.model_id == recognizer.model_id`).
5. Cosine similarity $\ge$ model-specific threshold (`0.0440` for `pretrained`, `0.0540` for `autoroll_v1`).
6. **Temporal Confirmation:** Same identity observed $\ge 3$ times within a sliding window of $1500\text{ ms}$.

Status Code Outputs:
- **`PRESENT`**: All criteria satisfied and temporal confirmation passed.
- **`PENDING_TEMPORAL`**: Recognized identity observed fewer than 3 times within window.
- **`REJECTED_SPOOF`**: Liveness score below threshold.
- **`LOW_QUALITY`**: Quality filter rejected image chip.
- **`INSUFFICIENT_CONFIDENCE`**: Cosine similarity below model threshold.
- **`INCOMPATIBLE_MODEL_TEMPLATE`**: Template generated by different `model_id`.

---

## 6. Privacy & Security Boundaries

- Raw face embeddings are **never** exposed through public API payloads or WebSocket broadcasts.
- Raw face images are processed transiently in memory and are **never** written to disk.
- Student templates store binary float32 L2-normalized 512-dimensional vector blobs with model metadata tags.
